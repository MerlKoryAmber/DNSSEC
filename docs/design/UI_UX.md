# Панель — внешний вид и поведение (UX-спецификация)

Общая спецификация для веб-панелей управления (не привязана к конкретному продукту, стеку или бренду).
Фиксирует **раскладку, поведение и роли элементов**. Тема (светлая/тёмная), палитра, цвета кнопок и шрифт — на усмотрение проекта.

Источник: squid-panel `docs/design/UI_UX.md`
(https://github.com/MerlKoryAmber/squid-panel). Ассеты бренда: Inter fonts,
маскот, favicon, `.brand-mark` — из того же репо.

## Общая раскладка
- **Слева** — вертикальная панель меню во всю высоту окна. Наверху — логотип/название, ниже — список разделов; при необходимости внизу — пользователь / выход / версия.
- **Сверху** — узкая полоса: слева название текущего раздела, справа — пользователь (и при необходимости меню: пароль, выход).
- **Под верхней полосой (по необходимости)** — панель действий раздела: основные кнопки, компактные фильтры. Не уезжает при прокрутке списка.
- **По центру/справа** — рабочая область с содержимым раздела.
- **Экран входа** — отдельная центрированная карточка с логотипом, полями логина/пароля и кнопкой входа. Остальное — только после входа.

## Границы экрана и размеры
- Раскладка опирается на **видимую область окна (viewport)**, а не на жёстко прошитые пиксели «как на одном мониторе».
- Высота оболочки (меню + верх + рабочая область) = **высота окна**; лишнее **не вылезает** за край экрана и не раздувает страницу вниз/вбок целиком.
- Ширины и отступы — через гибкую сетку / `min`/`max` / доли доступного места. Запрещены «магические» фиксированные высоты блоков контента, из‑за которых на низком экране обрезается таблица без прокрутки, а на высоком — огромная пустота или двойной скролл страницы.
- Длинный список/таблица занимает **оставшуюся** высоту под шапками (меню, top bar, toolbar, заголовок карточки) и **внутри себя** прокручивается. Не задавать высоту таблицы константой вроде «всегда 800px».
- На узком экране: боковое меню уезжает в выезжающую панель / гамбургер; рабочая область использует всю ширину; горизонтальный скролл только **внутри** таблицы, не у `body`.
- Модалки и тосты остаются **в пределах viewport** (не уезжают за край, не требуют скролла всей страницы, чтобы увидеть кнопки).

## Как прокручивается
- Боковое меню, верхняя полоса и toolbar раздела **не уезжают** вместе с содержимым.
- **Скроллится только рабочая область** (или внутренняя область длинной таблицы). Страница целиком горизонтально не едет.
- В боковом меню: если пунктов больше, чем по высоте — **скроллится список разделов**; логотип-шапка закреплена. Скроллбар меню можно скрыть визуально; прокрутка колесом при наведении на меню работает.
- Широкие таблицы — горизонтальный скролл **внутри своей рамки**.
- В длинных таблицах: заголовок блока/карточки над областью прокрутки; **заголовки столбцов закреплены** при прокрутке строк; фильтры — компактно над таблицей (или в toolbar), без лишней высоты «простыни».

## Меню и навигация
- Пункты меню — плоский список (иконки — по решению проекта; не раздувать декор).
- Текущий раздел **визуально выделен**.
- Переключение — по клику (полная перезагрузка или без — на усмотрение стека); заголовок сверху соответствует разделу.
- **Видимость по роли**: недоступное роли **не показывать** (не «серым»).
- Крупные разделы при необходимости — вкладки/якоря внутри раздела в той же манере.

## Кнопки
По значимости, не по конкретному цвету:
- **Основное действие** — самая заметная (акцент темы).
- **Второстепенное** — приглушённая/контурная.
- **Опасное** — стиль предупреждения темы; **всегда с подтверждением**.
- Компактные, ровные, без лишних иконок-украшений на каждой кнопке.

## Диалоги, подтверждения, сообщения
- **Никаких** системных `alert` / `confirm` / `prompt` и «голого» системного UX там, где можно оформить внутри панели.
- Подтверждение — окно внутри страницы (затемнение + карточка, «Отмена» / действие).
- Успех и ошибки — понятным текстом у формы и/или тостом панели; не сырой технический ответ пользователю.

## Формы и поля
- У поля — понятная подпись; короткое пояснение там, где без него легко ошибиться.
- Технические внутренние ключи API/БД на экране не светить без нужды; язык продукта (термины предметной области) допустим.
- Выбор из набора — переключатели, галочки, списки, а не «коды через запятую», если есть нормальный UI.
- Секреты — скрытое поле; отметка «задан»; пустое = «не менять», если так задумано.
- Загрузка файла — контрол панели с именем файла; не оставлять неподписанный системный вид.
- Группы полей — секции с заголовком.

## Таблицы
- Сортировка по клику на заголовок (где нужна).
- Фильтры сверху; явное применение, если не live-поиск.
- Заголовки столбцов и полоса фильтров **не уезжают** при прокрутке строк.
- Статусы — бейджи; цвета — за темой.
- Нет данных — **явная заглушка**, не пустота как «ещё грузится».
- Действия (Edit/Delete/Add) скрывать у ролей только на чтение.

## Тема и оформление (только требования)
- Тема и палитра — выбор проекта.
- **DNS Panel (lab):** тёмная Interros/gold как в squid-panel (`--ir-bg` `#0c121c`, акцент `#c9a96e`).
- Достаточный контраст; один акцентный цвет для активного пункта и основных кнопок; опасные действия отличимы; единый шрифт; консистентность экранов.

## Общие принципы
- Всё с пояснениями там, где ошибка дорого стоит; без необратимого без подтверждения.
- Никаких неожиданных системных окон браузера — оформление внутри панели.
- Верх и меню всегда на месте; листается содержимое.
- Содержимое **считается с размером окна**, а не с жёсткой сеткой одного разрешения.
